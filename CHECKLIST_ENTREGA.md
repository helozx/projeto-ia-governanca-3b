# Checklist final da entrega

## Equipe

- [ ] O nome do quarto integrante substituiu todos os campos pendentes.
- [ ] O grupo possui 4 ou 5 participantes.
- [ ] Todos conhecem seus papéis Scrum.

## Parte 1 — Relatório (3,0)

- [ ] O arquivo está em `.md`.
- [ ] O caso real está explicado.
- [ ] O texto não afirma que a investigação comprovou discriminação.
- [ ] Falhas nos dados e no modelo estão identificadas.
- [ ] Riscos de exclusão digital estão descritos.
- [ ] Regras de governança e regulamentação estão propostas.
- [ ] Fontes e links foram conferidos.

## Parte 2 — Scrum e Kanban (3,0)

- [ ] O quadro foi criado no Trello ou Miro.
- [ ] O link do quadro está no README.
- [ ] Os papéis estão visíveis.
- [ ] As histórias de usuário possuem critérios de aceitação.
- [ ] Os pontos seguem Fibonacci.
- [ ] Os limites WIP estão visíveis nas listas.
- [ ] Foi feita uma captura do quadro.

## Parte 3 — Colab (2,0)

- [ ] O notebook foi enviado ao Google Colab.
- [ ] Todas as células executam em ordem, sem erro.
- [ ] O CSV usado é o arquivo da pasta `dados/`.
- [ ] Há comentários e explicações em Markdown.
- [ ] O link está como “Qualquer pessoa com o link — Leitor”.
- [ ] O link do Colab está no README.

## Parte 4 — GitHub (2,0)

- [ ] O repositório está público.
- [ ] Cada integrante fez commits reais na própria conta.
- [ ] Foram usadas branches e Pull Requests.
- [ ] O histórico mostra a participação de todos.
- [ ] O link do GitHub está no README.

## Conferência final

- [ ] Nenhum arquivo contém senha, token ou dado pessoal real.
- [ ] Todos os links foram testados em janela anônima.
- [ ] O arquivo compactado abre corretamente.
- [ ] A apresentação foi ensaiada em até 10 minutos.
